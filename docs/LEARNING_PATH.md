# Transformer les bases en portfolio personnel

1. **Prendre en main** : lancer chaque exemple, lire le code et reproduire une erreur documentée.
2. **Choisir une spécialité** : gestion, sécurité, données ou infrastructure. Conserver deux ou trois projets principaux.
3. **Personnaliser les données** : utiliser un jeu de données non sensible, décrire sa provenance et expliquer le besoin.
4. **Approfondir le projet** : par exemple une interface de stock avec rôles et migrations, un index inversé pour la recherche, ou une exécution persistante des tâches du DAG.
5. **Mesurer** : produire de vrais résultats de tests et des mesures reproductibles avant de faire des affirmations de fiabilité ou de performance.
6. **Présenter** : enregistrer une courte démonstration et expliquer au moins une décision technique et une limite. Mentionner l’assistance IA utilisée et les modifications personnelles.
7. **Publier la démo** : choisir la visibilité du code puis configurer l’hébergement dans une étape séparée.
